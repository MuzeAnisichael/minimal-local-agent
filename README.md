# Minimal Local Agent 2.0

一个有状态的 Agent 执行内核，采用“大模型 + 工具”的混合架构。运行时自己掌握“规划 → 执行 → 校验”循环：
每一步都写事件和检查点，工具调用经幂等账本执行；进程中断后从检查点继续，失败或取消时补偿已写入的文件；
事件轨迹把输入、模型调用、工具结果和最终产物串起来，可以从任意产物回溯到它的来源。

PydanticAI 只用作模型调用层（`Model.request`），循环、状态和工具执行都在本项目内。
1.x 的代码保存在 `v1.1-archive` 标签，2.0 不兼容 1.x 的配置和状态库。

## 能做什么

| 能力 | 说明 |
| --- | --- |
| 任务规划 | 先生成结构化计划；校验失败时带着失败原因重新执行（`planning.max_replans`）；模型可用 `update_plan` 更新步骤状态 |
| 统一工具协议 | 内置文件工具、MCP 工具、子任务、控制工具都是同一个 `Tool`，经同一个执行入口，超时、取消、重试、审批、账本只实现一次 |
| 上下文预算 | 按 token 估算裁剪历史，以“步骤”为单位丢弃，保留一条摘要和当前计划；可选用模型做摘要 |
| 调用预算 | 请求数、工具调用数、输出 token、成本四项上限；子任务从父任务预留额度，用完结算回父任务 |
| 产物校验 | 文件内容、包含、缺失、哈希、回答包含、命令退出码；校验结果也记入事件轨迹 |
| 模型切换 | 按角色（plan / act / summarize）配置模型链，前一个失败自动换下一个 |
| MCP 接入 | 官方 `mcp` SDK，支持 stdio 和 Streamable HTTP；只暴露白名单工具，并标注读 / 写 |
| 受控子任务 | `run_subtask`：独立预算、工具只能是父任务可见工具的子集、不能再派生子任务 |
| 幂等与恢复 | 每次工具调用有幂等键；中断后按账本对账（已写入 / 未写入 / 部分写入 / 被外部改动），不会重复写也不会丢写 |
| 补偿 | 失败或取消时按逆序撤销本任务（含子任务）的文件写入；被别人改过的文件记为冲突，不覆盖 |
| 取消与超时 | 取消信号同时写进状态库，另一个进程里 `mla cancel` 也能生效；工具超时可自动重试 |
| 事件轨迹 | `mla trace` 打印事件树，`mla trace --artifact 路径` 从产物回溯到工具调用、模型调用、步骤和任务输入 |
| 评测 | 按任务族划分的评测集，固定模型与预算，对比基础循环、记忆、恢复策略的成功率、故障恢复率和每成功任务成本 |

## 安装

需要 Python 3.11+。

```bash
pip install -e ".[dev]"          # 开发依赖：pytest、ruff
pip install -e ".[dev,mcp]"      # 需要 MCP 时
```

## 快速开始

```bash
cp agent.example.toml agent.toml   # 按需修改模型配置，默认是本地 Ollama
mla run "把 config.ini 里的 debug 关掉" --events
```

`mla run` 默认在每次写文件前显示 diff 并询问；`--yes` 自动批准。校验规则可以写成 JSON 文件传入：

```bash
echo '[{"type": "file_contains", "path": "config.ini", "text": "debug = false"}]' > checks.json
mla run "把 config.ini 里的 debug 关掉" --checks checks.json --yes
```

## 命令

| 命令 | 作用 |
| --- | --- |
| `mla run GOAL [--checks F] [--yes] [--events] [--json]` | 执行一个任务 |
| `mla resume TASK_ID` | 从最近的检查点继续一个中断的任务 |
| `mla cancel TASK_ID` | 请求取消（对另一个进程中的任务也有效），取消后自动补偿 |
| `mla tasks` / `mla show TASK_ID` | 列出任务 / 查看结果和工具账本 |
| `mla trace TASK_ID` | 打印事件树 |
| `mla trace --artifact PATH` | 从产物回溯完整来源链 |
| `mla undo TASK_ID` | 手动补偿：撤销任务写入的文件 |
| `mla eval [--offline] [--strategies ...] [--no-faults] [--repeat N] [--out F]` | 运行评测 |

也可以用 `python -m minimal_local_agent ...`。

## 评测

```bash
mla eval --offline --out eval-report.json
```

评测集在 `evals/families/`，每个文件一个任务族：只读问答、单文件修改、多文件重构、MCP 工具接入、受控子任务、经验复用。
用例可以注入故障：写盘前或写盘后崩溃、工具超时、文件在写入前被外部改动、模型给出非法工具调用。

四种策略只是配置覆盖：

| 策略 | 恢复 | 重新规划 | 记忆 |
| --- | --- | --- | --- |
| baseline（基础循环） | 关 | 0 | none |
| memory（记忆） | 关 | 0 | episodic |
| recovery（恢复） | 开 | 2 | none |
| full（记忆+恢复） | 开 | 2 | episodic |

输出每个任务族、每种策略的成功率、故障恢复率（注入故障的用例里最终成功的比例）、每成功任务成本和 tokens
（所有用例的花费 / 成功数，失败用例的花费也计入）。

`--offline` 使用用例自带的脚本模型，结果确定，用来验证运行时机制（崩溃续跑、对账、重试、重新规划、记忆注入）是否生效，
CI 每次都跑；成本按名义价格计算，只用于策略之间的相对比较。去掉 `--offline` 则使用 `agent.toml` 里的真实模型，
这时结果才反映模型能力。当前离线结果（6 个任务族，18 个用例）：

| 策略 | 成功率 | 故障恢复率 | 每成功任务 tokens |
| --- | --- | --- | --- |
| 基础循环 | 50% | 11% | 3139 |
| 记忆 | 56% | 11% | 2673 |
| 恢复 | 94% | 100% | 2239 |
| 记忆+恢复 | 100% | 100% | 2077 |

### 真实模型结果（2026-11-19）

同一评测集，每个模型固定一个、预算相同，每种策略 18 个用例（其中 9 个注入故障）：

| 模型 | 策略 | 成功率 | 故障恢复率 | 每成功任务 tokens |
| --- | --- | --- | --- | --- |
| DeepSeek（deepseek-chat） | 基础循环 | 61% | 33% | 14748 |
| | 记忆 | 61% | 33% | 15211 |
| | 恢复 | 94% | 100% | 13135 |
| | 记忆+恢复 | 94% | 100% | 11866 |
| OpenRouter（qwen/qwen3-coder） | 基础循环 | 56% | 33% | 21732 |
| | 记忆 | 50% | 22% | 24775 |
| | 恢复 | 83% | 100% | 15140 |
| | 记忆+恢复 | 83% | 89% | 17471 |

恢复机制是成功率差异的主要来源；关键词检索式的记忆在相关任务上能省 token，但在无关任务上也可能分散模型注意力。

## 配置
