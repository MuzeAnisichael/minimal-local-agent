## Minimal Local Agent 2.0.0：有状态执行内核

2.0 把执行内核整体重写了一遍。1.x 是一次 `agent.run()` 外面套一层钩子，进程一断任务就丢；
2.0 由运行时自己掌握“规划 → 执行 → 校验”循环，每一步都写事件和检查点，工具调用经幂等账本执行。
进程被杀之后可以从检查点继续，不会重复写也不会丢写；失败或取消时自动撤销本任务写过的文件；
任何一个产物都能沿事件轨迹回溯到产生它的工具调用、模型调用和任务输入。

PydanticAI 只保留为模型调用层（`Model.request`），循环、状态和工具执行都在本项目内。

### 亮点

- **检查点与续跑**：任务状态（阶段、消息、计划、预算用量）每一步写入 SQLite 状态库，`mla resume TASK_ID` 从最近检查点继续。
- **幂等工具账本**：每次工具调用都有幂等键。中断后按账本对账（已写入 / 未写入 / 部分写入 / 被外部改动），已完成的调用直接重放结果。
- **补偿**：失败或取消时按逆序撤销本任务（含子任务）的文件写入；被别人改过的文件记为冲突，不覆盖。
- **跨进程取消与超时重试**：`mla cancel` 能取消另一个进程里的任务；工具超时按配置自动重试。
- **事件轨迹**：`mla trace TASK_ID` 打印事件树，`mla trace --artifact 路径` 从产物回溯完整来源链。
- **统一工具协议**：内置文件工具、MCP 工具、子任务、控制工具走同一个执行入口，审批、预算、超时、账本只实现一次。
- **规划与重新规划**：先生成结构化计划；校验失败时带着失败原因重新执行。
- **上下文与调用预算**：按 token 估算、以步骤为单位压缩历史；请求数、工具调用数、输出 token、成本四项上限。
- **按角色的模型路由**：plan / act / summarize 各配一条模型链，前一个失败自动换下一个。
- **MCP 接入**：官方 `mcp` SDK，支持 stdio 和 Streamable HTTP，白名单工具并标注读 / 写。
- **受控子任务**：独立预算、工具只能是父任务可见工具的子集、不能再派生。
- **按任务族的评测**：6 个任务族、18 个用例，可注入崩溃、超时、外部改动、非法调用等故障，对比基础循环、记忆、恢复三类策略。

### 评测结果

真实模型（每个模型固定一个、预算相同，每种策略 18 个用例，其中 9 个注入故障）：

| 模型 | 基础循环 | 记忆 | 恢复 | 记忆+恢复 |
| --- | --- | --- | --- | --- |
| DeepSeek（deepseek-chat） | 61% | 61% | **94%** | **94%** |
| Qwen3-Coder（OpenRouter） | 56% | 50% | **83%** | **83%** |

开启恢复后，注入故障用例的恢复率从 33% 提升到 89%–100%，每成功任务消耗的 token 也更少。
关键词检索式的记忆策略效果不稳定：在相关任务上能省 token，在无关任务上也可能分散模型注意力。

离线评测（脚本模型，验证运行时机制，CI 每次都跑）：记忆+恢复策略成功率与故障恢复率均为 100%。

### 不兼容变更

- 不兼容 1.x 的接口、配置文件和状态库，需要按 `agent.example.toml` 重新配置。
- 移除了 Web 控制台、实时观察面板、A2A 适配、记忆人工审核流程、回执哈希链。回溯改用 `mla trace`。
- 1.x 的最后一次提交保存在 [`v1.1-archive`](https://github.com/MuzeAnisichael/minimal-local-agent/tree/v1.1-archive) 标签。

### 安装

需要 Python 3.11+。

```bash
pip install "minimal-local-agent @ git+https://github.com/MuzeAnisichael/minimal-local-agent@v2.0.0"
# 需要 MCP 时
pip install "minimal-local-agent[mcp] @ git+https://github.com/MuzeAnisichael/minimal-local-agent@v2.0.0"
```

也可以直接安装本页附带的 wheel。

### 已知限制

- MCP 写操作无法对账和补偿，只有声明为 `idempotent` 的工具才会在中断后重放。
- 离线评测的数字来自脚本模型，只说明机制生效，不代表模型能力。
- 尚未发布到 PyPI。

### English summary

2.0 is a ground-up rewrite of the execution kernel. The runtime now owns the plan → act → verify loop and
persists every step: checkpoints in SQLite, an idempotent tool ledger with reconciliation after crashes,
reverse-order compensation of file writes on failure or cancel, cross-process cancellation, tool timeouts with
retries, and an event trace that links any artifact back to the tool call, model call and task goal that produced it.
PydanticAI is kept only as the model-call layer. Also new: role-based model routing with fallback, token-level
context compaction, call budgets, MCP (stdio / Streamable HTTP), controlled subtasks, and a per-task-family eval
suite with fault injection. With recovery enabled, success rate on real models rose from 61% to 94% (DeepSeek)
and from 56% to 83% (Qwen3-Coder). Not compatible with 1.x; the old code lives at tag `v1.1-archive`.
