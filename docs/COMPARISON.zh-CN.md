# 极简与本地 Agent 系统对比

调研日期：2026-08-10。本文只使用各项目官方文档和源码仓库。“取舍”表示范围和责任不同，
不代表项目缺陷。

## 一句话结论

Minimal Local Agent 不应该比拼功能数量，而应成为一个**小而可验证的本地 Agent 内核**：

1. 策略从真实工具 schema 中移除能力，而不是只靠提示词禁止；
2. 多文件变更以有上限的事务方式预览、批准、提交和撤销；
3. 历史、工具元数据、运行事件和哈希链凭证均可检查；
4. 用实际部署的工具面评测本地模型；
5. 默认边界没有 Shell、删除、远程网络、守护进程和隐藏编排。

## 快速对比

| 项目 | 主要目标 | 主要优势 | 相对本项目的取舍 |
|---|---|---|---|
| Minimal Local Agent | 可验证的本地文件任务 | 小型策略工具面、事务编辑/撤销、凭证、本地评测、受控 MCP | 没有 Shell、GUI、聊天渠道、浏览器、语义记忆、远程 MCP 或多 Agent |
| [smolagents](https://huggingface.co/docs/smolagents/main/index) | 极简可编程 Agent 库 | API 简洁、模型/工具无关、CodeAgent、本地模型、MCP | 持久化、工作区策略和耐久审计由应用实现；危险代码需要更强隔离 |
| [Qwen-Agent](https://qwenlm.github.io/Qwen-Agent/en/guide/get_started/features/) | 面向 Qwen 的完整 Agent 能力 | 工具解析、并行/多步调用、RAG、内置工具、MCP、流式和 Gradio | 范围更广且更偏 Qwen；最小权限文件策略与凭证由应用负责 |
| [nanobot](https://github.com/HKUDS/nanobot) | 轻量自托管个人助理 | 渠道、Web UI、记忆、调度、MCP、Shell/Web/文件工具、子 Agent | 凭据、进程、网络和运维边界明显更大 |
| [Goose](https://github.com/aaif-goose/goose) | 成熟可扩展桌面/CLI Agent | 多提供商、桌面/CLI/API、MCP 生态、丰富权限模式 | 运行时和扩展面更大，需要理解更多策略选择 |

## 具体取舍

### smolagents

smolagents 用极少代码即可组合模型和工具，同时支持工具调用与代码 Agent。需要快速实验、
多模型支持或生成代码执行时，它更合适。

Minimal Local Agent 直接提供工作区边界、确认流程、SQLite、可撤销事务和执行凭证，并有意
排除模型生成代码。smolagents 的[安全执行指南](https://huggingface.co/docs/smolagents/main/tutorials/secure_code_execution)
也明确区分受限本地执行与更强的 Docker/远程沙箱隔离。

### Qwen-Agent

需要深度 Qwen 适配、并行调用、RAG、代码解释器、Web/图像工具、流式或 Gradio 时，
Qwen-Agent 更强；它还提供[规划能力评测](https://qwenlm.github.io/Qwen-Agent/en/benchmarks/)。

Minimal Local Agent 通过 Ollama 兼容接口保持应用边界的模型独立性，关注具体文件工具能否
可靠使用，并把最小权限文件策略作为现成产品约束。

### nanobot

nanobot 已经是完整个人助理：聊天渠道、长期记忆、调度、Web/文件/Shell、MCP、子 Agent
和自动化都是核心能力。它适合常驻助理，但也必然需要保护更多密钥、服务和强能力。

Minimal Local Agent 没有常驻服务和渠道凭据，记忆保持为透明本地状态，并从核心排除进程
执行和远程网络工具。

### Goose

Goose 提供原生桌面、CLI、API、多模型提供商、大型 MCP 生态和多种审批模式。Minimal
Local Agent 的拒绝策略直接省略工具 schema，只审批受限工作区变更，并让五个内置工具可以
一次看懂。它的 MCP 更窄：本机 HTTP、显式工具名、无服务端提示/采样、结果有上限。

## 本项目更强的地方

- 五个内置工具和一个策略编译器，信任边界容易理解；
- 被拒绝的工具不会出现在模型 schema 中；
- 一次批准覆盖完整多文件 diff；
- 失败自动回滚，且文件未被再次修改时可以撤销；
- 本地历史、审计、事件、策略指纹和逐会话凭证链；
- 评测要求答案和工具事件同时正确，外部数据集还能声明状态和禁止工具；
- 没有队列、向量库、浏览器、守护进程或进程沙箱的运维负担。

## 本项目更弱的地方

- 只聚焦受限文本文件任务，不是通用桌面或个人助理；
- 精确替换比任意 patch 语法更窄；
- SQLite 会话不是语义长期记忆；
- 没有 token 流式输出和图形界面；
- 当前评测是回归冒烟测试，不是统计型排行榜；
- MCP 只支持本机 HTTP，并依赖操作者确认白名单工具确实只读；
- 因为不暴露进程工具，所以没有进程/容器沙箱。

## 已完成与下一步

| 状态 | 改进 | 价值 | 约束 |
|---|---|---|---|
| v0.2 | 机械只读模式与 diff 批准 | 可执行的能力边界 | 拒绝工具始终不进入 schema |
| v0.3 | 事务式精确编辑、预览、回滚、撤销 | 避免任意 patch 解析仍能安全编辑 | 文件数和完整 diff 有上限 |
| v0.4 | 运行时 API、策略、事件、迁移、凭证 | 明确嵌入与验证接口 | 强防篡改证据需要把链头保存到数据库之外 |

| 后续 | 完整持久化下的异步流式 | 降低感知延迟 | 最终历史和凭证必须完整 |

## 新能力准入原则

“极简”是持续约束。每项新能力必须回答：

1. 当前工具无法解决哪个已经测量的任务？
2. 解决它所需的最小权限是什么？
3. 如何限制、测试、审计和恢复它？

如果答案不清楚，该能力应放入适配器或更完整的 Agent 平台，而不是核心。
